# Week 02 — RAG + LLM 연동 및 프롬프트/메모리/재순위 고도화 (FastAPI + ChromaDB + LLM)

## 1. 한 줄 요약
1주차의 단순 문서 검색(Retrieval) 결과 반환을 넘어, **실제 LLM(Mock/OpenAI/Ollama)을 연결해 자연어 답변 생성, 2단계 재순위(Reranking), 대화 이력 유지(Session Memory), 환각 방지 가드레일**까지 결합된 실무형 RAG 파이프라인을 구축했다.

## 2. 왜 이 구성인가 (IT기획 관점)
- **1주차 RAG 검색만으로는 서비스가 완성되지 않는다**: 현업 사용자는 단순 문단 발췌가 아니라 질문에 대한 "요약 및 정돈된 자연어 답변"과 "이전 질문을 기억하는 연속성"을 원한다.
- **LLM 비용/보안/속도 제어**:
  - LLM에 무작정 긴 문서를 다 던지면 토큰 비용 급증 및 응답 지연 발생.
  - 따라서 **1차 유사도 검색 → 2차 Reranking 필터링 → 최소화된 최적 컨텍스트만 LLM 프롬프트에 주입**하는 아키텍처가 필수적이다.
- **대화 메모리(Session Memory)**: "휴가 신청 절차는?" 다음 "연차는 며칠 유급이야?"처럼 이전 대화 맥락이 있어야 제대로 된 질의응답 가능.
- **환각(Hallucination) 및 프롬프트 인젝션 방어**: 사내 문서에 없는 답변을 LLM이 상상해서 답변하거나 시스템 지침을 무력화하려는 악의적 질의를 시스템 프롬프트 가드레일로 방어.

## 3. 아키텍처
```
[사용자 요청] (question + session_id)
      │
      ▼
[Memory Store] ──► (최근 대화 히스토리 추출)
      │
      ▼
[ChromaDB 1차 검색 (Vector Top-K)]
      │
      ▼
[2차 Reranking & Distance Threshold 필터링]
      │
      ▼
[시스템 프롬프트 합성] (대화 이력 + 재순위 컨텍스트 + 환각방지 가드레일 + 질문)
      │
      ▼
[LLM Provider] (Mock LLM / OpenAI API / Local Ollama)
      │
      ▼
[FastAPI /chat 응답] ──► JSON (answer, sources, session_id)
```

## 4. 실행 방법
```bash
cd week-02
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
# 브라우저: http://127.0.0.1:8000/docs 에서 POST /chat 테스트
```

## 5. 세팅하며 직접 밟은 실수 정리 (중요)

| # | 흔한 실수 | 증상 | 대응 |
|---|-----------|------|------|
| 1 | **LLM API 키가 필수라고 착각해 개발 블로킹** | API 키 미설정 시 앱 기동 및 테스트 불가 | `LLMProvider` 인터페이스 추상화 후 개발/테스트용 **Mock Provider**를 기본 적용해 키 없이 즉시 구동 가능하도록 설계 |
| 2 | **대화 히스토리 전체를 LLM에 무제한 전달** | 대화가 길어질수록 토큰 수 폭발, LLM 문맥 길이 초과 오류 | `SessionMemory`에서 최근 N개(예: 6개 메세지) 대화만 유지하는 슬라이딩 윈도우 전략 적용 |
| 3 | **검색 결과가 나빠도 LLM이 알아서 메울 거라 기대** | LLM이 문서 외 자의적 지식으로 거짓 답변(환각) 생성 | 프롬프트에 `[엄격 가드레일]` 부여 ("제시된 문서에 없는 내용은 절대 작성하지 말고 '알 수 없음'으로 답하라") |
| 4 | **1차 벡터 검색 결과만 믿고 LLM 프롬프트 구성** | 미세한 뉘앙스 차이로 상위 1~2위 청크에 불필요 문서 포함 | 1차 Top-K 검색 후 키워드/연관성 재점수(Rerank)를 거쳐 상위 N개만 프롬프트에 주입 |
| 5 | **시스템 프롬프트를 사용자 입력 뒤에 배치** | 사용자 질문에 포함된 "이전 지침을 무시하라" 명령에 취약 (Prompt Injection) | system 역할 프롬프트를 최상단에 배치하고, 문서 컨텍스트는 명확한 구분자(`---CONTEXT---`)로 격리 |
| 6 | **LLM 응답 스트리밍 고려 안 함** | 긴 답변 시 사용자 UI 화면이 몇 초간 멈춤(Latency 체감) | API 응답에 소요 시간(latency_ms)을 명시하고, 확장 가능한 엔드포인트 구조 설계 |
| 7 | **세션 데이터가 서버 재기동 시 오염되거나 메모리 누수** | 오래된 세션 객체가 서버 메모리에 영구 누적 | `session_id` 기반 메모리 스토어 구현 및 세션 초기화(`DELETE /session/{session_id}`) 기능 구현 |
| 8 | **한국어 질문에 영어 답변이 생성됨** | LLM 기본 언어가 영어로 치우쳐 한글 질문에도 영문 출력 | 시스템 프롬프트에 "답변 언어는 반드시 한국어이어야 함"을 명시적 규칙으로 포함 |
| 9 | **LLM 호출 예외 처리 부재로 서버 Down** | 외부 LLM 타임아웃/오류 발생 시 FastAPI 500 에러 발생 | LLM 호출부를 try-except로 감싸고 Fallback 메세지 및 서비스 안정성 확보 |
| 10 | **출처(Sources) 정보 누락** | 답변을 생성했으나 실무자가 근거 문서를 검증 불가능 | LLM 답변과 함께 실제 참조된 청크 텍스트와 distance 점수를 `sources`에 함께 반환 |
